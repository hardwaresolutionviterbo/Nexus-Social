## 1. Obiettivo

Realizzare un catalogo gerarchico completo per la sezione SCAMBIA & VENDI di Piazly. Il catalogo
deve consentire agli utenti di:

- Pubblicare annunci di vendita.
- Proporre oggetti da scambiare.
- Regalare oggetti.
- Cercare oggetti da acquistare o ricevere.
- Effettuare proposte di scambio con eventuale conguaglio economico.

La struttura deve essere utilizzabile da smartphone, tablet e PC.

## 3. Identificativi e struttura database

Ogni categoria e sottocategoria deve avere: ID univoco stabile; slug univoco; nome visualizzato;
ID categoria padre, per le sottocategorie; posizione di ordinamento; stato attivo/disattivo; data
creazione e aggiornamento.

Esempi di identificativi: `motori`, `immobili`, `elettronica`, `casa-arredamento`, `motori-auto`,
`motori-moto-scooter`, `elettronica-smartphone`, `casa-arredamento-divani`.

Gli slug non devono cambiare quando si modifica il nome visualizzato.

Struttura relazionale con una tabella `marketplace_categories`:

| Campo | Tipo |
|---|---|
| id | UUID |
| parent_id | UUID nullable |
| name | TEXT |
| slug | TEXT UNIQUE |
| sort_order | INTEGER |
| is_active | BOOLEAN |
| created_at | TIMESTAMPTZ |
| updated_at | TIMESTAMPTZ |

Le categorie principali hanno `parent_id = NULL`. Le sottocategorie fanno riferimento alla categoria principale.

## 4. Tipologia annuncio

Ogni annuncio deve avere un campo `listing_type` con i valori: `sell` – Vendita; `swap` – Scambio;
`free` – Regalo; `wanted` – Cerco.

Non creare quattro sistemi di annunci separati: utilizzare un'unica struttura con tipologie differenti.

## 5. Campi annuncio

Campi generali: titolo; descrizione; categoria; sottocategoria; tipologia annuncio; prezzo;
condizioni dell'oggetto; località; foto multiple; data pubblicazione; stato annuncio; proprietario;
disponibilità spedizione; ritiro a mano.

Condizioni dell'oggetto: Nuovo; Come nuovo; Ottimo stato; Buono stato; Discreto; Da riparare.

Il prezzo deve essere obbligatorio per la vendita, facoltativo per lo scambio e non previsto per il regalo.
